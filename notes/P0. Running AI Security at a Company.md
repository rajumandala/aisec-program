# P0. Running AI Security at a Company

## What this part is

The [main course](https://github.com/rajumandala/aisec-notes/blob/main/00.%20Syllabus.md) secured one AI order assistant inside a broker's trading app, with its controls in code. [Part S](https://github.com/rajumandala/adlc/blob/main/notes/S0.%20AI%20in%20the%20SDLC.md) looked at the team that builds it with AI, and [Part M](https://github.com/rajumandala/ai-supplychain/blob/main/notes/M0.%20Model%20Supply%20Chain.md) at the models it depends on. All three looked at one system.

This part looks at the whole company. The broker now has many AI features from many teams, and a small security team. The questions change from "is this assistant safe?" to:

- Which controls should every team get for free, and which must each team build for its own business?
- Which features need a deep review, and which need none?
- How does the company know it is getting safer, and what does it report?
- What has gone wrong at other companies, and what would have stopped it?

The example stays the same broker, with the same people and the same controls. Where a control was built in the main course, the notes link to it.

## How the notes are built

The notes follow the same pattern as the earlier parts:

1. Each note starts from the problem the previous one ended on.
2. It adds one company-wide practice: a shared service, a process or a measure.
3. It shows the point with an example from the broker. Most of this part is design and process, so there is little code, and none of it has been run.
4. It lists the OWASP risks it meets, each with an example, the issue and the fix.
5. It ends on the next problem and links to the note that deals with it.
